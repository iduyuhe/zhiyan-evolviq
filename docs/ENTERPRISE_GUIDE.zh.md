## 一、平台能为企业解决什么（能力 → 痛点映射）

智衍不是「又一个 BI 看板」，而是把**工业 know-how 封装成 20 个可自主执行的智能体**。企业典型痛点与对应 Agent：

| 企业痛点 | 直接对应 Agent | 产出形态 |
|----------|---------------|----------|
| 缺料停线、替代料找不到 | supply_chain 📦 | 齐套率预警 + 替代方案 + 授权内自动锁料 |
| 排程靠 Excel、交期总跳票 | aps_scheduler 🧠 | 产能负荷图 + 瓶颈识别 + 再平衡建议 |
| 设备突发故障、非计划停机 | pm_maintenance 🔧 | 部件健康分 + 预测性维护计划 |
| OEE 算不清、损失说不明 | oee_optimizer ⚡ | 六大损失分解 + 改善任务 |
| 良率异常追不到根因 | yield_analysis 📈 / quality_trace 🔍 | 缺陷帕累托 + 端到端追溯链 |
| 能耗高、碳排无账、ESG 难交差 | energy_carbon 🌿 | 碳排核算 + 降碳机会（含回收期真算） |
| 成本科目糊涂、降本无抓手 | cost_analysis 💰 | 单位成本拆解 + 降本任务 |
| 需求与产能脱节、交期承诺虚 | demand_order 📊 | 产销协同 + 供给再平衡 |
| 库存积压或断料反复 | wms_logistics 🚚 | 库存健康度 + 自动补货 |
| 质量体系认证到期 / 法规违规 | compliance_q 🛡️ | 合规状态 + CAPA 自动生成 |
| 经营 KPI 散在多系统、决策慢 | executive_cockpit 🏢 | 驾驶舱 + 改善行动项 |
| NPI 项目延期、里程碑失控 | rd_npi 🔬 | 风险项目识别 + 加速建议 |
| 供应商绩效黑盒、合同管理乱 | procurement_manage 📑 | 供应商评分 + 评审 / 续签建议 |
| DFM/BOM/ECO 设计的可制造性 | dfm_check / bom_selector / eco_change | 设计期拦截制造风险 |
| SMT 换线慢、AOI 误报高 | smt_changeover / aoi_judge / ipc_standard | SMED 计划 / 阈值优化 / 标准判定 |

**一句话**：平台把"老师傅的经验"和"跨系统的数据"变成**7×24 在线、可审计、可放权**的数字员工。

## 二、你的企业适合现在上吗（就绪度自评）

### 2.1 强烈建议上（高匹配）

- ✅ 电子制造 / 半导体 / SMT 行业（种子数据即该行业风格，开箱最贴）
- ✅ 已有至少一个数据源（MES / ERP / SCADA / 能源表）可对接
- ✅ 有多系统数据孤岛、靠人工拉通报表的痛点
- ✅ 有"老师傅依赖"风险（关键工艺知识在少数人脑子里）

### 2.2 可以上但要分阶段（中匹配）

- 🟡 离散制造其他行业（汽车零配件、医疗器械）——需补行业种子数据，约 1–2 周
- 🟡 数据全在纸质 / Excel、无系统接口——先做"人工录入 → 结构化"过渡

### 2.3 暂不建议（低匹配）

- 🔴 纯流程型化工 / 连续生产（无 SMT / 半导体工艺语义，需大量定制）
- 🔴 完全无 IT 基础、连基本网络都没有的作坊
- 🔴 期望"买来即全自动无人干预"——平台是**人机协同**而非黑灯工厂替代

### 2.4 就绪度打分表（自测）

| 维度 | 0 分（无） | 3 分（部分） | 5 分（完善） |
|------|-----------|------------|------------|
| 数据源 | 全纸质 | 1–2 个系统 | MES+ERP+SCADA 齐全 |
| 网络 | 无内网 | 有局域网 | 有工业网+安全区 |
| 组织 | 无数字化岗 | 有 IT | 有数字化委员会 |
| LLM 策略 | 禁用 | 试点 | 已采购 API |

**≥12 分即可启动试点**；8–11 分建议先打数据基础；<8 分先做数字化启蒙。

## 三、落地实施方法论（三阶段）

> 核心原则：**先用种子数据跑通价值证明（POC），再接一个真实源验证，最后渐进扩到全厂**。绝不要求"一次性全接"。

### 阶段一：价值验证（2–4 周）

| 步骤 | 动作 | 产出 |
|------|------|------|
| 1 | Docker 一条命令部署（或访问演示环境 `43.153.172.52:3006`） | 可用平台 |
| 2 | 注入演示数据 `ZHIYAN_DEMO_DATA=1` | 真实行业风格数据 |
| 3 | 选 1–2 个最痛 Agent（如 supply_chain + aps_scheduler）做演示 | 给老板看量化结果 |
| 4 | 配一个 LLM API Key（DeepSeek / 混元 / 任一 OpenAI 兼容） | 推理可用 |

**退出标准**：业务主管认可"这东西能算出我们关心的数"。

### 阶段二：单源接入（2–4 周）

| 步骤 | 动作 | 工作量 |
|------|------|--------|
| 1 | 选**最高价值、最低阻力**的数据源（通常 OPC-UA 产线 or MQTT IoT 平台） | 选型 1 天 |
| 2 | 按《数据对接能力评估》映射节点 / topic / 字段 | 映射 3–5 天 |
| 3 | 改写对应 Agent 的 `tools.py` 数据源（分析逻辑不变） | 开发 3–5 天 |
| 4 | 灰度验证真实数据驱动的产出 | 验证 2–3 天 |

**退出标准**：至少一个 Agent 跑在真实数据上，结果可信。

### 阶段三：规模推广（持续）

| 步骤 | 动作 |
|------|------|
| 1 | 按"痛点优先级矩阵"逐个接入其余 Agent |
| 2 | 配置授权边界（见第四章），明确哪些动作可自动执行 |
| 3 | 建立"人类审批 → 效果反馈"闭环，逐步放权 |
| 4 | 接入知识图谱，打通跨 Agent 追溯 |

## 四、授权治理模型（企业怎么"放管结合"）

这是企业最关心的安全问题。平台**每个 Agent 有独立的授权边界**（`AuthBoundary`），由 9 个字段精确控制放权度：

| 字段 | 含义 | 企业怎么设 |
|------|------|-----------|
| `confidence_threshold` | 置信度阈值——Agent 多自信才允许自主执行 | 试点期设 0.85（紧）；稳定后降到 0.70（放） |
| `max_daily_autonomous` | 每日自主执行上限 | 高频 Agent（oee）设 20；低频（eco）设 15 |
| `auto_execute_actions` | 授权内可自动执行的动作白名单 | 如 `create_improvement_task` 可自动 |
| `require_approval_actions` | 必须人工审批的动作 | 如 `expedite_order`（加急）、`renegotiate_contract`（重谈） |
| `allowed_categories` | 允许操作的业务类别白名单 | 空=不限；可限定只动某产品线 |
| `price_tolerance_pct` | 价格容差%（涉及金额动作） | 设 5%=单笔波动超 5% 须审批 |
| `max_lock_qty` | 最大锁定量（涉及实物） | 设 0=不自动锁实物；设 N=允许锁 N 单位 |
| `enabled` | 边界是否启用 | 关掉即该 Agent 全走人工 |

### 4.1 企业放权三档模板

| 档位 | 适用期 | confidence | 自主动作 | 审批动作 |
|------|--------|-----------|---------|---------|
| **观察档** | 上线首月 | 0.90 | 仅生成报告 / 任务 | 全部 |
| **协同档** | 稳定后 | 0.75 | 生成任务 + 低风险执行 | 资金 / 实物类 |
| **自主档** | 充分信任 | 0.65 | 多数执行 | 仅战略级 |

> 平台提供「按效果调参」控制台：实时看**自主率**（放权度）和**批准率 / 驳回率**（人类信任度），据此动态微调阈值——**调参即时生效，不需重启**。

### 4.2 治理委员会职责

建议企业设"AI 治理小组"（业务+IT+合规各一人）：
- 每月审视各 Agent 的批准率，驳回率高 → 收紧阈值
- 审批战略级动作（加急、重谈合同、预算调整）
- 决定新 Agent 上线 / 旧 Agent 下线

## 六、行业落地剧本（三条线）

### 剧本 A：半导体 / 封测厂（最贴合，开箱即用）
- **主线**：supply_chain（齐套）→ aps_scheduler（排程）→ pm_maintenance（设备）→ yield_analysis（良率）→ quality_trace（追溯）
- **数据**：OPC-UA 接设备、MES API 接工单、ERP 接 BOM
- **首月价值**：缺料停线预警、交期风险识别、良率根因定位

### 剧本 B：SMT 电子组装厂
- **主线**：smt_changeover（换线）→ aoi_judge（误报）→ oee_optimizer（OEE）→ ipc_standard（标准）→ energy_carbon（能耗）
- **数据**：IPC-CFX（SMT 设备原生）+ MQTT（IoT 表）
- **首月价值**：换线时间压缩、AOI 误报降、能耗碳排核算

### 剧本 C：集团多工厂经营
- **主线**：executive_cockpit（驾驶舱）→ demand_order（产销）→ cost_analysis（成本）→ compliance_q（合规）→ procurement_manage（供应商）
- **数据**：各厂 ERP 汇总 + BI 抽取
- **首月价值**：经营 KPI 一屏、跨厂对标、合规风险早知

## 七、价值量化框架（ROI）

不要只算"省了多少人头"，要算**杠杆价值**：

| 价值维度 | 量化指标 | 典型改善（实测参考） |
|----------|---------|---------------------|
| 停线损失 | 缺料停线时长 ↓ | 齐套率 41.7%→100% |
| 交期履约 | 准时交付率 ↑ | 75%→91.7% |
| 能耗成本 | 单位能耗 ↓ | 识别降碳机会，回收期 1.8 年 |
| 质量成本 | 报废 / 返工 ↓ | 缺陷帕累托定位 |
| 决策效率 | 报表人工时 ↓ | 跨系统自动拉通 |
| 知识留存 | 老师傅经验数字化 | 不依赖个人 |

**ROI 公式（建议）**：
```
年收益 = 停线损失节省 + 能耗节省 + 质量成本降 + 人力释放
年成本 = LLM API + 服务器 + 1–2 人·月集成
回收期 ≈ 年成本 / 年收益   （多数场景 < 6 个月）
```

## 八、风险管控与合规

| 风险 | 平台机制 | 企业管理动作 |
|------|---------|-------------|
| Agent 误执行 | 授权边界 + 审批动作 | 观察档起步、逐步放权 |
| 数据泄露 | 多租户 `X-Tenant-Key` 隔离 | 内网部署、不暴露公网 |
| 外部依赖故障 | 韧性降级（PG→SQLite / Neo4j→内存 / 网关 simulated） | 监控网关状态 Tab |
| 模型幻觉 | 置信度阈值 + 人类审批 | 关键动作强制人工 |
| 合规审计 | 所有动作留痕 + 知识图谱追溯 | 定期导出审计日志 |

> **韧性降级是平台的硬保障**：除 LLM Key 外，没有任何外部依赖必须在线——PostgreSQL / Neo4j / 网关任一故障，系统自动回退且**永不宕机**。

## 十、常见问题（企业视角）

**Q：需要专职 AI 团队吗？**
不需要。1 名 IT（接数据）+ 业务主管（用）+ 治理员（调参）即可启动。平台是"平台 + 需配置"，不是"买来即用 SaaS"。

**Q：数据安全吗？能私有化吗？**
能。Docker 全栈可纯内网部署，数据不出厂。多租户隔离。`LLM_API_KEY` 是唯一出网点（调用模型），可用私有化模型（vLLM / Ollama）彻底不出网。

**Q：接真实数据要改多少代码？**
只改 Agent 的 `tools.py` 数据源（约 1–2 周/源），**分析逻辑零改动**。协议层已内置 Modbus/MQTT/OPC-UA/IPC-CFX 四类网关。

**Q：上了之后 Agent 会乱来吗？**
不会。每个 Agent 有独立授权边界，资金 / 实物 / 战略动作强制人工审批。所有动作可审计、可追溯。

**Q：和现有 MES / ERP 冲突吗？**
不冲突，是**增强层**。平台读取 MES/ERP 数据做分析与建议，不替换它们。可视为"坐在 MES 上面的 AI 大脑"。

**Q：能先试用再决定吗？**
能。演示环境 `43.153.172.52:3006` 已注入行业数据，可直接体验；或 Docker 本地一键起。
