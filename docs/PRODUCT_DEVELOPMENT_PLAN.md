## 0. 战略锚点（为什么是这个顺序）

战略已锁三条硬约束，直接决定开发优先级：

1. **路线 A 原生赋能者**：不推倒 ERP，给客户叠加「实时决策脑 + 全息真相源」。→ 网关实时流是「最撬动全局」的入口，必须第一个做。
2. **自主可控 Z 轴（A=1.0）**：Apache-2.0 全开源是护城河楔子。→ 所有基座代码必须可自部署、可审计，不依赖闭源服务。
3. **二十强 CCI 启示**：巨头的封顶项是「闭源 + retrofit」，我们的增长项是「开放网络引力 N」。→ 每版本只补最撬动全局的一环，用「可用」换「引力」，不堆功能。

**北极星**：客户经营决策「实时化率」（由实时孪生驱动、含实时字段的决策数 ÷ 总决策数）。当前 ≈ 0%，MVP 目标 ≥ 40%，稳态 ≥ 85%。

## 3. 实时孪生融合约定（接口契约）

为让「网关流 → 孪生体 → agent 推理」可复现、可测，定义能耗孪生 tag 约定：

- 网关/外部实时事件经 `registry.route_event("machine", values)` 上行，`values` 采用扁平键：
  - `energy_kwh__<line_id>`：实时周能耗（kWh）
  - `power_kw__<line_id>`：实时功率（kW）
  - `green_ratio__<line_id>`：实时绿电比例（%）
- `energy_carbon.analyze()` 扫描所有 `machine` holon 孪生体，解析上述键，**覆盖**种子基线对应字段，并重算 `carbon_t`，标记 `real_time=True` + `twin_source` + `updated_at`。
- 新鲜度：`updated_at` 距今 < 300s 视为 `fresh`，否则标 `stale`（仍用，但结论文案提示偏旧）。
- 无孪生数据 / 解析失败 → 整体回退种子基线，结论标注「无实时孪生流，使用种子基线」。

> 事实锚点纪律：孪生体只接收状态上行、绝不发起业务动作或改写业务数字；agent 仅「读」镜像。
