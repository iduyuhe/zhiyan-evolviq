## 一、战略层：定力与真实世界

### 1. 讨论期必须有终局（经验）
- 路线 A（原生赋能者：不推倒 ERP，叠加实时决策脑+全息真相源）经历多轮竞争评估后，靠 `MASTER_EXECUTION_PLAN.md` 总纲终结讨论——**一人公司的战略讨论必须有落章时刻**，否则永远在"再想想"。
- 教训：讨论期的每份竞争评估（西门子/美的/二十强 CCI）若不做收敛动作，都是沉没成本。

### 2. 工程自嗨陷阱（教训，最重要之一）
- 2026-08-01 目标达成度审计揭穿真相：**工程目标全达成（24 Agent/预设层/475 passed/双入口 PASS），业务北极星却 ❌（真实决策实时化率=0%）**——因为 DEMO_DATA=1，真实事件=0，真实客户 N≈0。
- 教训：**测试绿 ≠ 业务真**。工程度量（passed/部署成功）会掩盖"没有真实数据喂养"的空转。北极星必须绑定真实信号，否则一切都是演示。
- 铁律：北极星起跳 = 真实客户数据接入 + DEMO_DATA=0 之日；在此之前的"达成"都是工程达成，不是目标达成。

### 3. 不等客户，先造范式（经验）
- 研究案例模式：不等签约客户，直接锚定区域行业标杆上市企业（首例=中兴通讯 000063.SZ）做**公开数据推演**，对外匿名"某某通讯公司"。
- 教训：real_anchor 真名只存内部变量，任何外发 payload 零真名（两条红线：法律红线 + 私域/公开边界）——**匿名不是口号，是 `_assert_no_leak()` 矩阵 + compliance_reviewer 闸门三连验证**。

### 4. 先有后优，范围纪律（经验）
- 候选池锁死 6 行业、当前只做 1 个（通讯）；预设层先 3 套（设备库 6 类 9 台 + ERP 7 套 + MES 4 套）；新增 Agent 需杜总拍板（bid_intel 第 25 个）。
- 教训："不扩展新边缘"是**生产力纪律**：研究案例库加强靠"挖存量肥肉"（白名单 +2 字段、TS +2 字段、复用既有 JSX），0 新文件 0 新接口 0 新数据。

## 二、架构层：轻与韧

### 5. 通道级消费 = 零改动扩展（经验，架构最值钱的设计）
- 外圈 Agent 经 `env_context()` 从 UNS `CHANNEL_ENVIRONMENT` **通道级查询（不按 kind 过滤）** → 新增 customer_voice 源，5 个 Agent 自动受益，零 agent 改动。
- 前端 `EnvPerceptionPanel` 按 `source.label` 动态渲染 → 新源自动出现，零 UI 改动。
- 教训：**凡是"加东西要改 N 处"的设计，都埋着回归炸弹**；把"白名单/硬编码"换成"通道/动态渲染"，扩展成本从 O(N) 降到 O(1)。

### 6. 韧性降级是全栈铁律（经验）
- 外部依赖（PG/Neo4j/OPC-UA/AMQP）不可达自动回退（SQLite/内存图/simulated）；driver 延迟 import 放 connect() 内；FastAPI lifespan 陷阱（ASGITransport 不触发 lifespan → handler 内幂等自初始化）。
- 教训：**任何"外部挂了就 500"的代码都是设计缺陷**；降级不是异常路径，是第一路径。

### 7. 事实锚点铁律（教训）
- StrategyTuner 只调阈值（confidence∈[0.5,0.95]），绝不改业务数字；bid_intel 无信号时诚实输出「捕获 0 个」而非编造。
- 教训：**AI 产品最容易死在自己的"看起来合理"上**——演示数据冒充真实、推测冒充事实，一次被戳穿全盘失信。

## 三、安全层：凭证与供应链

### 8. GitHub 凭证教训（教训，代价最高）
- GH013 事件：旧 PAT 硬编码进提交 → GitHub Secret Scanning 推送保护拒绝 → 全历史清洗 + 强推。
- 铁律：**PAT 明文出现即泄露**（UI/截屏/日志）；凭证只走 `_gh_token.py` 共享读取器或服务器 .env；推送被拒先查 GH013。

### 9. 企微/数据源凭证纪律（经验，2026-08-02 确立）
- 企微 corpid/secret/agentid、招投标 API Key：**只进服务器 .env**，代码/日志/响应零明文；未配置优雅降级（/wecom/status unconfigured 不阻塞平台）。
- 教训：**把"凭证缺失"当一等状态设计**，而不是等凭证到了才写代码——框架先立、衔接等凭证（杜总定调）。

## 四、工程层：测试与部署

### 10. 全量回归与连锁断言（教训）
- 每轮必跑全量 pytest（当前 586 passed）；**改一个全局默认值会连锁 N 处断言**——FREE_MAX_SOURCES 3→4 连锁 3 处、新增 Agent 24→25 连锁 4 处（registry/onboarding/compliance/unlock 三圈）。
- 铁律：改全局常量/计数前先 `grep` 全部引用；新增 Agent 前先查计数断言。

### 11. 白屏三层防御（经验，杜总底线）
- 骨架屏 `#zhiyan-boot` + App ErrorBoundary + runtimeGuard 全局自动重载；每次部署 smoke_check 双入口验证。
- 教训：**"对外通信中断"是战略级事故**，不是 bug；白屏 = 失联 = 失信。

### 12. 构建/工具环境坑（教训清单）
- vite 版本号从 git HEAD 注入 → **必须先 commit 再 build**（否则水印滞后一个 commit）。
- Git Bash 无 sleep 二进制；agent-browser 必须直用 Windows .exe + `set viewport <w> <h>` + Windows 风格路径；受控沙箱 safe-delete 拦目录删除 → 构建旁路 `mv -f dist dist_old_bak`。
- 教训：环境坑要**沉淀成记忆/技能**，每次踩一次 = 每次浪费一轮。

## 五、产品层：多端与分面

### 13. 移动端三阶递进（经验，2026-08-02 定调）
- ①手机版 H5（响应式，已完成）→ ②企微自建应用 H5（免登+推送，骨架就绪）→ ③小程序（最后，手续最重）。
- 教训：**"手机版"和"小程序"不是二选一，是递进**；先 H5 验证价值，再上小程序手续，顺序天然正确。
- 踩坑：响应式顶栏 `flex flex-wrap` 必须配 `lg:flex-nowrap`（否则桌面端也 wrap 拐弯遮挡）。

### 14. 前后台分面（经验，2026-08-02）
- 单体 SPA + 角色化 Tab 过滤（ADMIN_ONLY_TABS 13 管理类仅 admin 可见）= 前后台效果，架构零改动。
- 教训：**先回答"用户到底该看到什么"再做界面**；管理入口对业务用户可见是观感+噪音双损失。

## 六、缺口：主动性缺失（本次讨论的落点）

### 15. Agent 全部被动（教训，架构级缺口）
- 半年里所有 Agent 都是**人提问 → 应答**；系统从不主动发现问题。
- 北极星「决策实时化率」的真实含义应该是：**风险发生 → 系统主动识别 → 主动推决策**，而不是"用户想到才来问"。
- OpenClaw（小龙虾）HEARTBEAT 心跳模式（每 30 分钟主动巡检、无异常静默、有异常才说话）恰好是这一缺口的现成样板。
- 结论：**「主动性」是本半年最大的架构级缺口，也是从"演示系统"走向"决策系统"的分水岭**——心跳自触发方案由此而来（见方案文档）。
