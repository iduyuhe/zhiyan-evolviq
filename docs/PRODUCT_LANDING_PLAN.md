# 1. 产品定义与北极星

## 1.1 产品一句话
**智衍 = 制造企业的「全息孪生社会操作系统」**：让人、机、料、法、环成为自治协作的智能体（holon），在钱学森综合集成研讨厅式的孪生层里实时感知、推理、决策、进化——而不是给一套滞后账本接个聪明大脑。

## 1.2 三层产品价值（递进）
| 层 | 客户感知 | 对应架构层 | 成熟度 |
|---|---|---|---|
| **看见** | 5M 全要素实时孪生大屏，经营状态一目了然 | 物理层 + 孪生层镜像 | 雏形（twin_feed 已接状态） |
| **决策** | agent 基于实时孪生给出可执行建议，人终审 | 孪生层三主义活循环 | 起点（阶段 1 下半场） |
| **进化** | 系统从每次执行后果中自学习、自修正策略 | 元层自进化 + 蓝弧 | 雏形（P2 已建） |

## 1.3 北极星指标（North Star）
**客户经营决策的「实时化率」** =（由实时孪生驱动、含实时字段的决策数）÷（同期总经营决策数）。
- 滞后账本时代 ≈ 0%；全息孪生社会目标 ≥ 60%（首年）、≥ 85%（稳态）。
- 它是"滑稽感"是否消除的可量化标尺，也是销售讲故事的锚。

## 1.4 辅助指标（护栏用，见 §7）
决策周期缩短率、隐性知识沉淀量（经审批进经验库的条目数）、锚定率（抽取信号挂实体比例）、测试零回归率。

# 2. 产品分层架构 → 产品模块矩阵

把"全息孪生社会"三层映射为可售卖、可交付的产品模块。

## 2.1 三层与模块归属
- **物理层（Physical）**：真世界的接入与执行。网关/IIoT、五路感知适配器、执行回写桥（ERP/MES 写回）。
- **孪生层（Twin）**：虚拟社会的运行。holon 孪生体（twin_feed 状态）、孪生 agent 推理、三主义活循环、综合集成研讨厅（推演环境）。
- **元层（Meta）**：社会的治理。身份与授权（AuthorizationEngine = holon 权限边界）、本体 Ontology、自进化版本栈、人审闸门。

## 2.2 产品模块矩阵（基础设施 + 20 agent）

| 模块 | 所属层 | holon 角色 | 当前状态 | 后续动作 |
|---|---|---|---|---|
| 网关四协议（OPC-UA/MQTT/Modbus/IPC-CFX） | 物理 | resource holon 接入 | ✅ | 配置 UI 带连通性验证（§8 护栏） |
| twin_feed 孪生体状态层 | 孪生 | 全 holon 镜像 | ✅ v20.6 | 增薄/厚孪生分级存储 |
| UNS 统一事件总线 | 孪生 | 事件归一 | ⬜ 阶段 2 | 五路适配器 + collab 源 |
| 三主义活循环引擎 | 孪生/元 | 真相循环 | ✅ 雏形 | 阶段 4 显式蓝弧回流 |
| 智衍工业经营本体（Ontology） | 元 | 符号固化 | ✅ | 升格命名，超越 Palantir 静态 Ontology |
| AuthorizationEngine（20 边界） | 元 | holon 权限 | ✅ | 薄/厚 holon 治理面板 |

| `supply_chain` / `wms_logistics` | 孪生 | thick agent（料） | ✅ | 已走 live，扩 collab 源 |

# 4. 阶段 1 下半场细案（下一个动手项）

**为什么是它**：上半场已让孪生体"有状态、可读"，但 agent 推理还没"用"它——等于建了镜子没人照。下半场是"孪生社会真正活起来"的最小一步。

**动作**：
1. 在 `BaseAgent.analyze()` 内注入 `twin_context()`（已就绪，安全降级），作为推理上下文的实时孪生块。
2. 选 `energy_carbon` 做端到端：模拟 OPC-UA 流 → `twin_feed` 更新能耗孪生体 → `analyze()` 读孪生体 → 产出"实时能耗/碳排 + 建议"结论（含实时字段）。
3. 写 `scripts/verify_twin_reasoning.py`：模拟流驱动 → 断言结论含实时字段 → 全量测试零回归。
4. 验收：真实/模拟流驱动 agent 出含实时字段结论；韧性降级不破（网关不可达时回退 seed + twin_context 空值安全）。

**验收标准**：
- [ ] `energy_carbon.analyze()` 在模拟流下产出含 `real_time_*` 字段结论
- [ ] 网关不可达时回退 seed / 孪生空值，agent 不崩
- [ ] 全量测试零回归（目标 ≥ 123 passed）
- [ ] demo 脚本可一键复现端到端

# 5. MVP 与首个客户场景

## 5.1 MVP 定义（最小可卖切片）
**全息孪生社会的"看见 + 单域决策"切片** = 网关实时接入（物理层）+ 单域 agent 实时孪生（孪生层）+ 人审闸门（元层）。
- 不做：全 20 agent 实时化、全五路隐性捕获、完整蓝弧（那是 v22+）。
- 做：1 个真设备域（能耗或设备健康）跑通"实时看见→agent 建议→人终审→回写"。

## 5.2 推荐首客场景：**设备健康 / 能耗孪生**
- **为什么**：最直观（大屏实时曲线）、最短 ROI（省电费/降停机）、数据最干净（网关直采，无滞后账本依赖）、最易 demo。
- **交付物**：docker 最小栈（沿用 `docker-compose.deploy.yml`）+ 网关节点映射清单 + 孪生大屏（v22.5 前可用简易面板）+ 人审后台。
- **部署形态**：客户现场 1 台边缘机跑 runtime + 网关；云端 demo-host 仅作演示。
- **接入口径**：OPC-UA 节点表（客户给）/ MQTT topic 约定；无真设备用 simulated 网关验证链路。

## 5.3 首客验收（客户成功门槛）
- 实时化率（该域决策）≥ 40%（MVP 期）
- 决策周期较原账本模式缩短 ≥ 50%
- 隐性知识沉淀（该域）经审批 ≥ 10 条/月

# 6. 商业化与生态路径

## 6.1 授权模式（沿用开源策略）
- **OSS 基座**：网关 + twin_feed + UNS + 元层治理（Apache-2.0，可自部署）。
- **商业 agent 包**：领域 agent（energy_carbon / equipment / aps / supply_chain 等）按订阅授权，含更新与陪跑。
- **不推倒 ERP**：路线 A——客户已有 ERP/MES 作执行回写桥，智衍装"实时决策脑"。

## 6.2 定价（建议，待杜先生定）
- 基座：免费 OSS（社区 + 生态引流）。
- 商业 agent：按 agent/年订阅 + 实施服务费。
- 陪跑/共建：工业5.0产业生态联盟的培训+咨询+孵化（杜先生主线，高毛利）。

## 6.3 生态协同（已有资产直接用）
- **公众号「工业5点0产业生态联盟」**：持续发"全息孪生社会"系列（已建草稿待发），建认知、引流。

- **联盟陪跑孵化**：首客从联盟成员中挑（信任成本低、数据口径顺）。

## 6.4 竞争站位（对外话术锚）

# 8. 风险护栏与发布纪律

## 8.1 沿用铁律
- **韧性降级**：外部（PG/Neo4j/OPC-UA/AMQP）不可达自动回退（SQLite/内存图/simulated），绝不阻断启动。
- **事实锚点**：StrategyTuner 只调阈值，绝不改业务数字/动作。
- **人审护栏**：prompt/事实/经验规则先入 proposed/draft，显式审批才生效，绝不自动应用。
- **分段开源**：本地积累 commit，成熟后分段推 GitHub，不裸推单 agent。

## 8.2 产品新增风险与兜底
| 风险 | 表现 | 兜底 |
|---|---|---|
| 孪生层脱离物理（模型幻觉） | agent 基于陈旧/虚构孪生决策 | 信息补录蓝弧（行为主义纪律）是保险丝；twin_context 带 ts，超期标 stale |
| 过度仿真（全孪生陷阱） | 法/环也建重物理仿真，成本高无收益 | 薄 holon 用法/环薄孪生（规则/约束孪生，不仿真） |
| 噪声拦截过度 | 人/社交/会议信号真知被误杀 | HITL 抽检 + 人审通过率监控（§7.3） |
| 假接（配而不通） | 网关配了连不上，比没有更危险 | 配置 UI 必须带连通性验证（§2.1 网关项） |
