## 0. 一句话定位

把智衍从"只感知围墙内"的封闭系统，升级为**同时感知体内（①–⑤路）与体外（⑥路）的物理世界开放系统**——政策、行情、竞品、供应链风险、客户公开声音进入全息真相源，让决策实时化率的覆盖面从车间级拉升到战略级。

## 2. 落实计划（三阶段，最小验证优先）

> 节奏原则不变：每次只补最撬动全局的一环，跑通再下一环。启动前提 = 杜先生解除"技术推进暂停"并拍板首批源。

### 阶段 α：最小验证（v30.0）——"官方源两类，一条链路跑通"

| ID | 任务 | 落点 | 验收（机器可断言） |
|---|---|---|---|
| α1 | UNS 增 `environment` 路 | `src/runtime/uns.py`：`CHANNEL_ENVIRONMENT` 入 `ALL_CHANNELS`；事件带 `credibility` 字段 | 事件入总线可查可回溯，`channel_counts` 含 environment |
| α2 | 首批两类官方源适配器 | `src/runtime/connectors/env_policy.py`（政策法规 RSS/公告）+ `env_market.py`（原材料行情公开 API）；沿用 connectors 目录 lazy-import 与韧性降级铁律 | 模拟源+真实源各跑通；源不可达自动回退 simulated，不阻断 |
| α3 | 可信分级门 | `credibility=official` 直接锚定；`authoritative/general` 进 `_needs_review`（复用邮件通道审批机制） | 单测断言：非官方信号必带 `_needs_review`，绝不直锚 |
| α4 | 捕获即锚定 | `tacit_capture` 扩展或新建 `env_capture`：environment 信号 → 经验库 + KG draft（带来源与 credibility 标注） | 信号 100% 锚定实体（MAT/SUP/POLICY），无主信号拒收 |
| α5 | agent 消费验证 | 选 1 个高杠杆 agent（建议 `supply_chain` 或 `demand_order`）在 analyze 上下文中引用 environment 信号 | 至少 1 条决策结论含环境信号引用字段 |
| α6 | 冒烟+零回归 | 新增 `tests/test_environment_perception.py`；全量 pytest | 全量测试零回归（≥216 passed 基线） |

**α 阶段边界**：不做前端配置 UI、不做智能推荐、不接非官方源——先证明"外部世界的一条官方信号能走完 感知→锚定→决策引用 全链路"。

### 阶段 β：租户自定义筛选（v30.5）——"筛选权交给客户"

### 阶段 γ：智能推荐与自进化（v31）——"环境感知长出自进化基因"

| ID | 任务 | 落点 |
|---|---|---|
| γ1 | 源推荐 | 按租户行业/物料/供应商画像推荐可订阅信息源（draft 形式，人审后订阅） |

## 3. 系统性影响分析与应对优化措施

> 原则：第⑥路是**五路→六路的自然生长**，复用 UNS+捕获+锚定+审批骨架，零推倒。但"零推倒"不等于"零影响"——以下九个层面逐一分析。

### 3.1 UNS 事件总线（影响：低 · 结构性）
- **影响**：`ALL_CHANNELS` 增一路；事件 schema 增 `credibility` 字段（仅 environment 必填，其余路可空——向后兼容）。environment 不进 `ROUTEABLE_CHANNELS`（不路由孪生体——外部信号不是设备状态）。
- **风险**：环境源轮询高频入总线，内存环形缓冲被外部信号刷穿，挤掉网关实时事件。
- **应对**：① environment 路独立配额（如环形缓冲按 channel 分区或设该路上限）；② 默认低频轮询（小时级，行情类可 15 分钟）；③ 聚合去重——同一政策/同一行情 tick 只入一条。

### 3.2 tacit_capture / 知识图谱（影响：中 · 质量关键）
- **影响**：捕获面新增一类"外部事实"，KG 出现新实体类型（`POLICY:` 前缀等）与新关系（`affects/regulates`）。
- **风险**：**噪声污染真相源**——外部信息量大、真伪混杂，一旦垃圾进 KG，"全息真相源"招牌反被砸；实体链接错误（外部文本提到的"铜"链错物料）。
- **应对**：① credibility 分级门是硬闸（非官方绝不直锚）；② 沿用"抽取即锚定，无主信号拒收"纪律——挂不上租户实体的信号不入库只归档；③ KG 中环境事实带 `source_url+credibility+ts` 三标注，可审计可回滚；④ 定期"环境事实过期清理"（政策有效期、行情时效性），过期自动降权。

### 3.3 Agent 路由与决策（影响：中）
- **影响**：agent 决策上下文多一类环境信号；未来可能新增 `environment_scan` 类 agent。ROUTING_RULES 若增词条，须守"按语义紧密度插入不追加末尾"铁律。
- **风险**：环境信号与车间实时信号在上下文中争位，冲淡实时决策主线；agent 引用了过期/低信度外部信息产出错误建议。
- **应对**：① 环境上下文注入设条数上限+按相关性打分排序（γ2 前用简单关键词匹配）；② 决策结论引用环境信号时**必须带来源标注**（与事实锚点铁律同构：引用可溯源，不改写业务数字）；③ 建议先不新增 agent，让存量 agent（supply_chain/demand_order/strategy 类）消费，避免路由表扰动。

### 3.4 审批流 / 人审护栏（影响：中 · 复用为主）
- **影响**：`_needs_review` 队列多一类来源，审批量上升。
- **风险**：审批积压 → 客户嫌烦全放行 → 筛选形同虚设。
- **应对**：① 官方源直锚（不占审批队列）是第一减压阀；② β 阶段关键词/阈值预筛在入队前完成；③ 审批面板按 credibility 分组批量操作；④ 监控告警三件套增加"环境审批积压"指标（复用 v28.3 monitoring 骨架）。

### 3.5 多租户与数据隔离（影响：中）
- **影响**：同一外部源（如铜价）可服务多个租户，但筛选规则、锚定结果、推荐模型必须按租户隔离。
- **风险**：源抓取按租户重复执行浪费成本；或反过来共享不当造成租户间信息泄漏（A 租户的物料画像出现在 B 的推荐里）。
- **应对**：**抓取层共享、语义层隔离**——原始外部信号平台级抓一次（无租户私有信息），进入筛选/锚定/推荐后严格 tenant-scoped；推荐模型的画像特征绝不跨租户。

### 3.6 性能与成本（影响：低-中）
- **影响**：新增外部 HTTP 轮询与文本抽取（LLM 调用量上升）。
- **风险**：外部 API 限流/收费失控；LLM 抽取成本随源数量线性涨。
- **应对**：① 优先免费官方渠道（RSS/公告页/公开行情 API）；② 抽取前先规则预筛（标题关键词命中才走 LLM）；③ 按租户成本开关+频率上限（β4）；④ 缓存与增量抓取（Last-Modified/ETag），绝不全量重拉。

### 3.7 安全与合规（影响：高 · 红线）
- **影响**：系统首次主动向公网发起持续性抓取。
- **风险**：爬取受限内容的法律风险；外部内容含恶意载荷（SSRF/注入）；行情数据转售的授权问题。
- **应对**：① 白名单制——只接公开合法渠道（RSS/官方公告/授权 API），源准入即审计；② 外部内容一律当**不可信输入**处理：长度截断、HTML 剥离、URL 不回环内网（SSRF 防护）、payload 不进 prompt 模板的指令位（防注入）；③ 行情类源核对许可条款，仅内部决策引用不对外转发原文；④ 不碰公网社交账号与个人隐私（与④社交通道边界一致）。

### 3.8 前端 Studio（影响：低）
- **影响**：β3 新增配置页、γ4 大屏视图。
- **风险**：新页面引入运行时错误——触碰**白屏零容忍铁律**。
- **应对**：新组件全部包在既有 ErrorBoundary 之内；上线必过 smoke_check 冒烟门禁；fetch 全走 authHeaders() 三铁律；构建过 tsc+vite 双检。

### 3.9 韧性降级（影响：低 · 铁律直接适用）
- **影响**：外部源天然不稳定（网站改版/API 停服/网络抖动）。
- **应对**：韧性降级铁律直接套用——源不可达自动回退 simulated/跳过，绝不阻断主流程；源健康状态进 `/connectivity` 聚合面板；断流超阈值走监控告警（复用网关断流告警范式）。

### 3.10 影响总评

| 层面 | 影响度 | 是否需新机制 |
|---|---|---|
| UNS 总线 | 低 | 否（加常量+配额） |
| 捕获/KG | 中 | **是：credibility 分级门 + 过期清理** |
| Agent 决策 | 中 | 是：环境上下文限额+来源标注 |
| 审批流 | 中 | 否（复用+分组优化） |
| 多租户 | 中 | **是：抓取共享/语义隔离两层制** |
| 性能成本 | 低-中 | 否（预筛+缓存+开关） |
| 安全合规 | **高** | **是：源白名单+不可信输入处理** |
| 前端 | 低 | 否（守白屏铁律） |
| 韧性 | 低 | 否（铁律直接适用） |

**结论**：架构层面零推倒、六路自然生长成立；真正要新建的机制只有三个——**credibility 分级门、租户两层隔离、外部输入安全处理**。这三个都在 α/β 阶段内置，不留技术债。

## 4. 依赖与排期约束

- **不依赖** A1 子域名 HTTPS（环境感知是出站抓取，无需入站回调——这点比④社交通道的落地条件更宽松）。
- **依赖**：杜先生拍板 ① 首批源确认（建议：政策法规 + 原材料行情）② 启动时机（当前技术推进暂停中）。
- **建议排序**：α 阶段可作为暂停解除后的首个技术动作之一，与 A1（子域名架构）并行不冲突——一个纯后端出站、一个纯网络架构。

## 5. 验收北极星

- α：至少 1 个 agent 的决策结论引用了真实官方环境信号（带来源），全量测试零回归。
- β：某租户在界面上自定义筛选规则并"先测试后保存"生效。
- γ：推荐的采纳/驳回行为可查、且反哺后推荐命中率有可测提升。
- 战略层：对外叙事从"车间实时决策脑"升级为"**感知体内体外的物理世界开放系统**"，写入白皮书与对外物料（杜先生终审）。
