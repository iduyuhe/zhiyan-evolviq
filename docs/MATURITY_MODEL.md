# 智衍 EvolvIQ · 工业智能体成熟度模型（v3.0 · 三阶段演进 × 六级成熟度 × 自主可控度）

> **承接文档**：`PRODUCT_LANDING_PLAN.md`（产品版本路线图）+ `STRATEGY_SYSTEM_ROADMAP.md`（战略）+ `HOLOGRAPHIC_INFO_SOURCE_ARCHITECTURE.md`（架构）+ `COMPETITIVE_EVALUATION_MIDEA.md` / `COMPETITIVE_EVALUATION_SIEMENS.md`（竞争现实校验）
> **本模型回答**：产品路线图回答"我们交付什么"，本模型回答"客户/系统的工业智能处于什么范式、什么水平"。它是销售与陪跑的**诊断工具**——给客户定位 (Stage, Level) 双坐标 → 推荐对应版本跃迁；也是北极星指标（实时化率）的分级刻度。
> **核心命题（v3.0 重写要点）**：制造企业的工业智能不能只用"做到了哪一级"衡量——**同一 Level 可能建在滞后账本上（retrofit），也可能建在原生孪生上（native）；同一范式可能闭源被厂家锁死、客户被动等节奏，也可能开源自主、客户自己定节奏，自由度天差地别**。因此 v3.0 把单轴"成熟度"升级为 **三轴坐标系**：X 轴=六级成熟度（状态刻度）、Y 轴=三阶段技术演进（范式刻度，含 AI / AI+ / AI-native）、**Z 轴=自主可控度（开源↔闭源，客户自由度刻度）**。三轴正交，组合才是真实定位。

---

# 0. 三轴模型总览

| 轴 | 名称 | 刻度 | 锚点 | 回答的问题 |
|---|---|---|---|---|
| **X · 成熟度 Level** | L0–L5 | 状态刻度 | 决策实时化率（0%→85%+） | 做到了多好？ |
| **Y · 演进阶段 Stage** | AI → AI+ → AI-native | 范式刻度 | 真相源性质 + 数据底座 | 用什么范式做？ |
| **Z · 自主可控度 Autonomy** | 闭源 ↔ 开源 | 自由度刻度 | 客户节奏主动权 + 数据主权 | 客户有多少主动权？ |

- **任一企业的真实定位 = 坐标 (Stage, Level, Autonomy)**。
- 只看 Level 会误判：巨头（AI+）可到 L3–L4，但带 SAP ECC / S/4HANA 包袱；智衍（AI-native）当前 L1–L2，但范式在最右列——二者不同行不同列，不能直接比 Level。
- 只看 Stage 会空洞：必须落到 Level 才有可交付的切入点。
- **只看 Stage/Level 仍漏了最关键的一维——客户是否被厂家锁死节奏**。巨头（AI+，L3–L4）几乎全在 Z 轴"闭源"端；智衍（AI-native，L1–L2）在 Z 轴"开源"端。这一维决定客户是"被动等厂家带节奏"还是"自己定节奏"——**是客户自由度的最高标志**。
- 三轴才客观：**既看清"差距是什么性质"，也看清"客户到底被谁控制"，更看清"下一步卖什么"**。

# 1. 三阶段技术演进路线（Y 轴定义 · v2.0 新增）

> 缘起：用户指出"2026 年前的产品基本非 AI 原生，巨头 retrofit 在 SAP 传统 ERP 上"。这把"巨头领先"拆开——他们的 AI 是**应用层领先 + 底座滞后**的非对称结构。三阶段即刻画"AI 嵌入系统的范式代际"。

## 1.1 Stage 1 — AI（AI 叠加期 / AI-as-Assistant）

- **核心命题**：传统信息化系统（ERP/MES/PLM）是绝对核心与唯一真相源；AI 是外挂"助手层"——问答、报表生成、预测性维护告警、文案。
- **真相源**：账本（SAP ECC / 传统 MES 库），滞后、批处理。
- **数据底座**：传统 ERP（多为 SAP ECC 或早期 S/4HANA），**强锁定，迁移极重**（ECC→S/4HANA 需 12–24 月+）。
- **AI 角色**：被动响应、不进决策回路、无自治行动。
- **实时性**：本质批处理（MRP 至今非高峰跑批）。
- **代表**：绝大多数制造企业现状；Midea / Siemens 的**底座层**。
- **典型天花板**：L2。
- **典型陷阱**：即用户所言"快决策脑接滞后账本"的滑稽——AI 改不了底座滞后，只是把滞后包装得好看。

## 1.2 Stage 2 — AI+（AI 增强 / 融合期 / AI-retrofit）

- **核心命题**：AI 深入业务回路——多智能体协作、自治循环、预测+执行闭环；但**仍 retrofit 到 legacy 数据骨干**（S/4HANA / ESB / MES），真相源仍是账本主导、AI 增强之。
- **真相源**：账本仍主导，AI 在边缘做实时增强（实时总线补偿部分滞后）。
- **数据底座**：S/4HANA / ESB / MES（仍 SAP 系，迁移沉重）。
- **AI 角色**：多智能体、A2A、宣称自主进化；部分自治行动（具身机器人进厂）。
- **实时性**：部分实时（总线层），但账本批处理基因 + 数据模型僵化仍在。
- **代表**：**Midea 智能体工厂、Siemens Industrial AI OS**（均叠在 SAP/MES 之上；其公开报道原话"MES/ERP 继续作为数据底座，AI 在此基础上升级"）。
- **典型天花板**：L4。
- **典型陷阱**：被 2004 ECC / 2015 S/4HANA 底座锁定，迁移极重；"领先"主要是资金/数据/认证，非架构纯净；经营层隐性（人/社交/会议）无入口。

## 1.3 Stage 3 — AI-native（AI 原生期）

- **核心命题**：从设计第一天以 agent / holon / twin 为核心；真相源是**活全息孪生社会**（三主义合一活循环），账本退居执行回写与审计。
- **真相源**：全息孪生活循环（物理层与孪生层实时同步质量），非任一账本 / 图谱。
- **数据底座**：无账本锁定，直接接物理 holon 实时孪生（twin_feed）；可旁路 SAP、可写回 SAP。
- **AI 角色**：元 holon 编排 holon 社会；人 holon 终审；自进化受人工审批闸门。
- **实时性**：全实时。
- **代表**：**智衍 v20.6+**（born-native，无 legacy、无 SAP 锁定）。
- **当前坐标**：(AI-native, L1–L2) —— 范式领先但工程化早期。
- **典型陷阱**：缺数据飞轮、工程化待补、无硬件/认证；L1–L2 要长大需真实首客启动飞轮。

## 1.4 三阶段跃迁门槛（演进路线本身）

- **AI → AI+**：必须打破"账本为唯一真相源"，让 AI 进决策回路（多智能体、自治循环）。
- **AI+ → AI-native**：必须**脱钩 SAP/MES 底座锁定**，把真相源重建为活孪生社会。这是巨头最难、最慢的一步——因为 legacy 债（组织惯性、硬件栈锁定、旧账本拖拽），非加点功能可追。

# 2. 六级成熟度定义（X 轴 · 重锚到阶段）

> 实时化率锚：L0≈0% → L5>85%。每一级标注"可达阶段"——Level 与 Stage 不等价。

| Level | 名称 | 实时化率 | 可达阶段 | 关键能力 | 对应版本 | 跃迁门槛 | 典型陷阱 |
|---|---|---|---|---|---|---|---|
| **L0** | 滞后账本态 | ≈0% | AI | 仅静态记录 | — | 上 BI | 把 ERP 当真相源 |
| **L1** | 单点可视 | 0–10% | AI | 局部看板/告警 | — | 接实时源 | 只可视不决策 |
| **L2** | 实时孪生引擎 | 10–40% | AI+ → AI-native | 单域实时孪生+建议 | **v21.0** | 多域融合 | 伪实时(仅总线层) |
| **L3** | 综合集成态 | 40–60% | AI+ 高段 / AI-native | 五路综合集成+隐性捕获 | **v21.5** | 闭环回写 | 漏隐性通道 |
| **L4** | 蓝弧闭环态 | 60–85% | AI-native | 执行后果回灌修正 | **v22.0** | 自进化治理 | 孪生脱离物理 |
| **L5** | 全息孪生社会态 | >85% | AI-native only | 全息+自进化+人终审 | **v22.5+v23.0** | — | 过度仿真 |

> 注：巨头（AI+）可到 L3–L4 但带 SAP 包袱；智衍（AI-native）当前 L1–L2 但范式领先。**成熟度模型因此必须双轴**——单轴会以为"我们差三代想错了"，双轴才知差距主要是资金/数据飞轮/认证，可绕开。

# 3. 评估维度（9 维 · v2.0 较 v1.0 增加 3 维）

> v1.0 仅 D1–D7（含 D7 原生度）。v2.0 把"三阶段"操作化为两个新增维度 **D8 真相源性质 / D9 底座锁定度**，使 Stage 轴可被客户自评估量化。

| 维度 | 代号 | 测什么 | 各阶段典型表现 |
|---|---|---|---|
| 感知广度 | D1 | 五路覆盖（网关/外部/人/社交/会议） | AI 仅网关；AI+ 加外部；AI-native 全五路 |
| 孪生深度 | D2 | 孪生是否 agent 化、是否反作用 | AI 几何镜像；AI+ 部分活；AI-native 活 agent |
| 决策实时性 | D3 | 实时化率 | 随 Level 升 |
| 闭环完整性 | D4 | 信息补录蓝弧是否闭合 | AI+ 起部分；AI-native 完整 |
| 自治与治理 | D5 | 授权/人在环 rigor | AI-native 最强（AuthorizationEngine） |
| 自进化能力 | D6 | 反思学习+采纳度 | AI+ 宣称；AI-native 受闸门 |
| **演进阶段** | **D7** | **AI / AI+ / AI-native 定位（= Y 轴）** | **即 Stage 本身** |
| **真相源性质** | **D8** | 账本主导 / 账本+AI增强 / 全息孪生活循环 | 区分 retrofit 与 native 的本质 |
| **底座锁定度** | **D9** | SAP ECC 锁定 / S/4HANA 混合 / 无账本原生 | 巨头重锁；智衍零锁 |
| **自主可控度** | **D10** | 闭源(厂家定节奏) / 部分开源(可审不可改) / 开源(客户自主·数据主权) | 巨头闭源锁节奏；智衍 Apache-2.0 开源 |

# 4. 三阶段 × 六级 演进-成熟度矩阵（核心新增）

图例：● 典型可达　◐ 可达但非典型/带包袱　○ 基本不可达

| Stage \ Level | L0 | L1 | L2 | L3 | L4 | L5 |
|---|---|---|---|---|---|---|
| **AI** | ● | ● | ◐ | ○ | ○ | ○ |
| **AI+** | ● | ● | ● | ● | ◐ | ○ |
| **AI-native** | ○ | ◐ | ● | ● | ● | ● |

**读法（关键结论）：**
- **AI 阶段天花板 L2**：叠在账本上做不出全网实时——这是 retrofit 的硬上限。
- **AI+ 阶段天花板 L4**：仍被 SAP 批处理基因 + 数据模型僵化卡住，难到 L5。
- **只有 AI-native 能到 L5**：全息孪生社会态必然是 native 范式（无账本锁定 + 活孪生）。
- **智衍坐标 (AI-native, L1–L2)**；**巨头坐标 (AI+, L3–L4)**。二者不同行不同列，不可直接比 Level——这是"不被现象迷惑"的量化体现。

# 6. 客户诊断 → 双坐标 → 切入建议

**步骤：**
1. 用 §5 矩阵勾选，定 **Stage**（多数客户在 AI，部分先锋在 AI+）。
2. 用 §4 矩阵 + 实时化率，定 **Level**。
3. 坐标 (Stage, Level, Autonomy) → 推荐动作。Autonomy=闭源 的客户，即便 Level 高，也优先推"开源脱绑"切入——把节奏主动权交还客户，而非继续被厂家带节奏。

| 客户坐标 (Stage, Level) | 痛点 | 智衍切入点 | 对应版本 |
|---|---|---|---|
| (AI, L0–L1) | 滞后账本、无 AI | 轻量可视看板，埋 twin_feed 采集，不碰 SAP | v20.6 起点 |
| **(AI+, L2–L3)** | SAP 底座已滞后、想用 AI 又不想再陷迁移泥潭 | **轻量经营孪生看板（不绑 SAP）**——切巨头绑定痛点 | v21.0 / v21.5 |
| (AI+, L3–L4) | 已上智能体但被 ECC 锁死、隐性无入口 | 经营层隐性捕获 + 治理审计模块（补巨头空白） | v21.5 / v22.0 |
| (AI-native, 任意) | 同范式早期玩家 | 联盟共建 / Ontology 标准共建 | v22.5+ |

**智衍自身坐标 (AI-native, L1–L2)** → 首客应优先找 **(AI+, L2–L3) 且苦于 SAP 锁定**的企业——连巨头内部（如西门子能源 16 个 ECC 环境在迁移）都在逃 ECC，说明这是真实、广泛、巨头自己解决不了的空白。

# 7. 自评估清单（输出双坐标）

客户逐项勾选，先定 Stage（D7/D8/D9），再定 Level（D1–D6），最后定 Autonomy（D10）：

**A. 范式轴（定 Stage）**
- [ ] 真相源是 ERP/账本，AI 仅做助手 → **AI**
- [ ] AI 进决策回路、多智能体，但数据仍来自 SAP/MES → **AI+**
- [ ] 真相源是活孪生社会、无账本锁定、直接接物理 → **AI-native**

**B. 成熟度轴（定 Level）**
- [ ] 有结构化 ERP/MES 数据（≥ L0）
- [ ] 至少一域状态实时可见（≥ L1）
- [ ] 某 agent 基于实时数据给可执行建议且人终审（≥ L2）
- [ ] 人/社交/会议信号被采集并锚定进知识库（≥ L3）
- [ ] 执行后果自动回流并修正后续策略（≥ L4）
- [ ] 全要素自治协作 + 系统自进化无人工干预仍稳健（≥ L5）

**C. 自主可控轴（定 Autonomy / D10）**
- [ ] 核心系统闭源，路线图与节奏完全由厂家掌握，定制/迁移需等厂家 → **闭源**
- [ ] 可审计、部分开放，但不可自行修改或本地私有部署 → **部分开源**
- [ ] 核心基座开源（如 Apache-2.0），可审计、可改、可本地部署、数据主权归己、自己定节奏 → **开源**

最终定位 = (Stage, Level, Autonomy) 三坐标，对表 §4 / §6 取行动。自主可控度低的客户，即便 Level 高，也要提示"被厂家锁节奏"风险。

# 8. 智衍定位与竞争启示（结合 SAP 底座洞察）

- **巨头坐标 (AI+, L3–L4)** 但 **D9 底座锁定 = SAP ECC / S/4HANA**——结构性枷锁。ECC 自 2020 停售、2027 停主流支持；迁移 12–24 月+；批处理基因（MRP 非高峰跑批）持续限制上层语义丰富度。其"领先"主要是资金/数据/认证，非架构纯净。
- **智衍坐标 (AI-native, L1–L2)** 但 **D9 = 无账本原生**——born-native 相对 retrofit 巨头的**本质区别，不是弱项**。
- **楔子因此从"经营层长尾"扩大到"任何想脱钩 SAP 账本锁定、又要 AI 的企业"**——包括巨头内部想逃 ECC 的部门（西门子能源即例）。
- **第三轴（自主可控度 D10）是更锋利的楔子**：巨头无论多先进，产品全闭源、路线图与节奏由厂家掌握，客户本质是"被动等"。智衍选 **Apache-2.0 开源**，把"何时用 AI、怎么用、数据归谁"的决定权交还企业——客户可审计、可本地部署、可自己定节奏、不被绑定。对"吃过 SAP/巨头闭源绑定苦头"的企业，这是比技术范式更直击痛点的理由：**不能让客户再等厂家慢慢带节奏**。
- **不被现象迷惑**：巨头 L4 是带债的 L4；智衍 L2 是无债的 L2，且站在 2026 原生拐点起点。差距主要是资金/数据飞轮/认证——可用"轻量 + 开源 + 联盟陪跑"绕开，而非硬碰巨头主场。

# 9. 与路线图 / 北极星的关系

- **实时化率 = 成熟度的量化代理**：L0≈0% → L5>85%。
- **版本节奏 = 跃迁的供给**：v21.0 供给 L1→L2，v22.0 供给 L3→L4，一一对应。
- **三阶段 = 跃迁的范式约束**：v21.0 起点即 AI-native（不接 SAP 账本），确保智衍产品永不在 AI/AI+ 行——这是路线 A（原生赋能者）的刻度保证。
- **有机落实的统一语言**：双轴让"每次只补最撬动全局一环"有了客户侧刻度——先补木桶最短板（见 §5），而非堆功能。
