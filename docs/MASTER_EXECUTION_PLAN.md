### §1.5 商业全链条闭环总览（一张图看懂 11 条决策如何咬合）

今日五批定调（⑥环境感知 → G 楔子 → G5 对标 → 无感转型 → 行为导航 → 共生环）不是六件孤立的事，而是**一条获客-转化-留存-进化的完整商业链条**，每一环的输出恰好是下一环的输入：

```
【获客】环境感知⑥（决策2/3，S1内核）
   │  纯公开信息 → 企业免费即用，零部署零风险
   ▼
【造感】G5 行业智能化对标（决策5，S1源③+S2轨道二）
   │  真情报造差距感 + platform_insight 透明呈现我方优势
   ▼
【转化】无感转型三圈解锁（决策8，§3.5）
   │  外圈免费4 agent → 中圈上传1个文件（付费线/价值跳变）→ 内圈私有化
   ▼
【导航】智能体推荐·行为导航（S3第④层，§3）
   │  读客户行为不猜需求，推荐语=「你关注的X，配合Y能算出Z」
   ▼
【留存+进化】共生进化环（决策9，§3.6）
      客户反馈 → 脱敏审核 → 开源 Issue → 自进化 → 「因你而进化」回告
      └──同时破生态 N=0：客户成为真需求第一供给方，六柱飞轮获得第一推动力
```

**链条的三个关键性质**：
1. **同一套代码，两种包装**：整条链的技术载体就是 v30/v31 主线（S1→S2→S3），商业模式不产生额外开发主线——这是决策 4「与 v30 α 合并排期」的深层含义。
2. **每一环都有红线**：白屏门禁（获客入口绝不能白）、F4 可信治理（G5 广告不伪装情报）、脱敏审核门（反馈不出内网）——商业加速不豁免任何一条。
3. **闭环自度量**：三圈转化事件（§3.5 纪律3）+ 推荐埋点（S3④）+ 反馈-Issue-版本链（§3.6）是同一套数据底座，链条效果自己会说话。

**链的起跑线：杜特第 0 号用户（决策 10）**——上述链条在对外推向陌生客户之前，先在自家公司（上海杜特企业管理咨询有限公司）走一遍。这不是理论的"测试"，而是**我们自己的公司真的用起来**，用自己的培训/咨询/系统集成客户池验证获客路径。链上的每一环都在自己人身上跑通了，才推给外部客户。

## 1.6 战略范式总纲：研究案例模式 + 两阶段实例化框架（顶层，2026-07-29 杜总定调）

> **本节地位**：顶层战略范式。所有外部接口开发、案例库建设、获客叙事、产品定位均须照此执行。详细实现见 §3.7（研究案例模式）与 `docs/ENTERPRISE_PROFILE_SCHEMA.md`（现状描述接口规范）。

### 一、核心洞见：企业软件「价值交付时序」范式断点

传统企业软件（ERP/CRM/SaaS）卖给客户时是一套**空壳**——价值要等客户自己灌数据、配流程、做集成后才慢慢长出来（行业数据：60%~75% ERP 项目失败或严重超支，价值实现以"月/年"计）。

本范式翻转该时序：

```
公开数据 + 行业数据 + 企业披露（极大丰富）
    ↓ 智能体在客户到来之前预载行业智能
客户启用瞬间 → 拿到的不是空表单，而是「已经活着的行业体系」
    ↓ 客户自己的内部数据只是「在已活基座上的价值倍增器」
启用即有商业价值与使用价值，ROI 直接显现
```

**关键校准（杜总 2026-07-29 确认）**：对外统一叙事用 **「内部 = 价值倍增器」**，而非"内部只是连接点"——避免低估集成价值、也避免客户误判"接根线就完事"。预载公开行业智能是默认底土，内部实时数据是已活基座上的 premium 增长。

### 二、七柱思想体系

- **P1 研究案例模式**：不等签约，以区域行业 top-3 上市企业为研究案例；对外匿名「某某行业·某某客户·某某公司」，内部锚定真实公司用公开数据推演。首例锚定 = **中兴通讯（000063.SZ）**（对外仅显"某某通讯公司"）。
- **P2 案例驱动接口实例化**：所有外部接口按此模式——接口契约现在定义（适配器+降级桩），真实连通性留到具体案例出现时实例化；系统不因物理世界集成未就绪而停滞。两种锚：**数据类用真实公开数据，集成类用标准/参考实现**。
- **P3 案例库四重身份**：行业分析资产 + 教学/培训素材 + **产品活体本体**（非等用户填数据的空壳，本身就是行业体系）+ 公众号/生态获客内容引擎。
- **P4 价值交付时序范式断点**：启用即活体行业体系，ROI 直接显现；外部公开情报为默认底土，内部数据为价值倍增器。
- **P5 两阶段实例化框架**：公开预载活体 → 企业「现状描述+凭证」→ 接口实例化 + 组织/实体入租户 KG → 客户专属实例；映射 G 模式三圈解锁（免费看行业 → 价值显现后自愿给凭证开内圈）。
- **P6 操作节奏**：agent 提推荐（行业+锚定候选），杜总点确认。
- **P7 全球定位**：enterprise software 价值交付范式断点；对工业 SME SaaS 有 category-defining 潜力；成色取决于推理质量 + 校准闭环 + 匿名风控。

### 三、接口成熟度三态（可度量系统完善度，防"看似全通=真通"）

| 状态 | 含义 | 对外呈现 |
|---|---|---|
| ① 未定义 | 该外部接口尚无契约 | 不可见 |
| ② 接口就绪 | 适配器+降级桩+来源标记（`_source_mode`），可演示 | 演示态，明确标注"模拟/参考实现" |
| ③ 真实集成 | 具体案例中实例化（凭证/密钥就位） | 真实态，可标注"已融合客户数据" |

**铁律**：桩态（`_source_mode=simulated`）**绝不可冒充**真实态；对外演示必须显式标注来源，不欺骗（杜总底线）。

### 四、两条红线（杜总 2026-07-29 确认）

1. **🔴 法律红线**：触碰法律的事不干，一切在**法律允许范围**内做。多行业匿名案例若可反推归因 + 结论偏差 = 名誉/证券类暴露 → 发布前**合规闸门**（agents 抽偏检查 + 杜总/团队终审，参照公众号免责声明纪律）。
2. **🔴 私域/公开边界**：真实客户入驻后，其**私域数据**与案例库**公开推演**须**明确区分呈现**，禁把"公开推演"冒充"已融合客户数据"。

### 五、范围纪律（防摊大）

- **行业候选池**（暂定，不主动扩展）：半导体、3C、新能源汽车、通讯、光伏、工程机械。
- **当前只做 1 个**：通讯行业 → 中兴通讯（000063.SZ）单案例跑通、质量优先（先有后优）。
- 扩展随教学推进 + 客户拓展**自然发生**，不预先铺开。

### 六、案例库 schema 钩子

每个研究案例 = `{行业, 匿名标签, real_anchor(内部), 公开披露主题, 推荐接口清单(供同行业客户入驻时驱动接口推荐), 校准记录}`。详见 `docs/ENTERPRISE_PROFILE_SCHEMA.md`。

### 七、范式发动机与案例库本体（Agent 落地，2026-07-29 Phase 1）

原 20 个 agent 全为「内部运营型」（制造执行/供应链/经营战略/需求），无专职研究案例编排者。范式突破后补齐四类职能缺口，Phase 1 实装：

- **`industry_research`（范式发动机）**：拉取 `CHANNEL_ENVIRONMENT` 的 disclosure/benchmark/policy 信号 → 建匿名「某某X公司」画像 → 调度 4 外圈 agent(research_case 模式)推演 → 对齐 real_anchor 出校准报告。结果严格不外泄真实锚定名（real_anchor 仅存内部变量）。
- **`case_curator`（案例库活体本体）**：拥有案例库，列/汇总案例、挂 `recommended_interfaces`、生成教学双版（对外匿名 / 对内真名）。首例种子 = 通讯·`case_telecom_2026`（real_anchor=中兴通讯，仅 internal 视图）。
- **4 外圈 agent 加 `mode`**：`executive_cockpit`/`supply_chain`/`compliance_q`/`cost_analysis` 的 `analyze()` 加 `mode: tenant|research_case` + `case_id`；research_case 模式不写租户作用域记忆（原子行动恒空），数据作基准占位。
- **后续相位（待触发）**：Phase 2 企业入驻实例化→`enterprise_onboarding`；Phase 3 多案例规模化→`compliance_reviewer` 合规闸门；行业对标推演(⑤)先并入 `industry_research` 不单列。

### S2 · v30.5 β SaaS 化 + 租户自定义筛选（G 模式落地）（✅ 已完成，2026-07-28 收口 commit 289f2e3，344 passed + 双入口冒烟 PASS）

**目标**：同一套内核的第二种包装——「外感知先行」免费版可对外给企业试用。

- **S2-1** 筛选规则模型+配置 API+前端面板（复用「先测试后保存」闸门范式）。
- **S2-2** G5 轨道二：`platform_insight` 类型+界面明示「来自智衍平台的建议」，与情报相邻呈现。

### §3.6 「共生进化环」——情绪价值与客户共成长机制（2026-07-27 杜总定调）

**核心命题**：系统不只提供功能价值，还提供**情绪价值**；客户与平台**相互成长**——客户的想法与不满直接流向开源平台驱动进化，进化再回告客户。一次不满 = 一次进化的种子 = 一次信任加深的机会。

**四步闭环机制**：

1. **产品内零摩擦反馈**：每条情报/每个 agent 结论旁常驻轻量反馈位——「👍 有用 / 👎 不准 / 💡 我有想法」+ 可选自由文本。不满不是流失信号，是**最高价值的进化燃料**，界面文案明示"你的每条反馈都会推动平台进化"。
2. **脱敏审核门 → 开源平台**：反馈经**自动脱敏**（剥离租户名/业务数据/敏感字段）+ 复用 `_needs_review` 人工审核后，转为 GitHub Issue（标签 `from-customer`），公开进入路线图。
   - 🔴 **红线**：未经脱敏+审核的客户反馈**绝不出内网**；客户可选署名/匿名，**默认匿名**；涉及客户私有数据的反馈只在租户内闭环处理，不上开源平台。
3. **平台自进化**：我方+社区响应 Issue → 修复/新功能 → 版本发布。反馈 ↔ Issue ↔ 版本三向链接、全程可溯源（与 F4 溯源能力同一套肌肉——客户可以点开看到"我的反馈现在走到哪一步了"）。
4. **「因你而进化」回告**：版本发布自动触发个性化进化通知——"您 X 月 X 日提出的 XX，已在 vXX 上线"，附 changelog 与 Issue 链接。情绪价值三件套：
   - **被听见**：任何反馈 48 小时内必有首次回音（哪怕只是"已收到、已立项"）；
   - **被点名**：进化归功到人（匿名则归功到"一位制造业用户"）；
   - **被陪伴**：租户「成长档案」——使用天数、已解锁圈层、贡献的进化数、被采纳的想法数，让客户看见自己和平台一起变强的轨迹。

**战略意义（一石三鸟）**：
- **破生态 N=0**：开源社区最缺的不是代码是**真实需求**——客户反馈让 Issue 有了持续的真需求供给，外部贡献者有的放矢，六柱飞轮从此有了第一推动力。
- **留存护城河升维**：客户在平台上积累的不只是数据，还有**自己的贡献足迹**——迁移成本从功能成本变成情感成本。
- **与蓝弧同构**：客户反馈 = 平台级的"后果回流认知层"——单租户内 agent 靠蓝弧自进化，平台整体靠共生环自进化，**平台自身也进了三主义活循环**。对外叙事完整了：企业是活的，平台也是活的。

**实施纪律**：①脱敏审核门强制、无例外；②48h 首响应是硬 SLA，做不到宁可不上线此功能；③进化通知只发与该客户反馈相关的内容，绝不群发刷存在感（否则情绪价值变情绪骚扰）；④「成长档案」数据仅本租户可见。

**落点**：S2 增反馈入口+脱敏管道+48h 响应看板；S3 增「因你而进化」通知与成长档案；常青线 B 升级为「客户反馈→Issue→响应→回告」运营环（不再只是每周巡检）。
