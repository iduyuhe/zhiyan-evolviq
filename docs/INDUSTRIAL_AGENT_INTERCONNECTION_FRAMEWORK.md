# 工业智能体互联框架（Industrial Agent Interconnection Framework）

## 思想白皮书 · 智衍路线 v1

> 本文是"思想落地"层交付物，作为后续技术落地与应用落地的上游输入。
> 框架不追求完备——抓住主线，渐进展开。用"我们的语言"定义工业互联网智能体。

---

### 0. 一句话定义

当 AI 进入**物理AI**状态——它不只处理文本，而是与一个持续存在、与物理世界一一对应的**数字孪生对象**绑定，并在其上附着**记忆、技能、知识图谱**三类属性，再被**治理底座**横切约束——这就构成了"工业智能体互联"的整体框架。

---

### 1. 为什么是"物理AI"状态（论证起点）

通用智能体的记忆通常是 ephemeral（上下文窗口，关掉即没）或 generic RAG（检索公开文档，跟你的工厂无关）。它**没有载体**：没有一个持续存在、与物理产线一一对应的对象让它往上面写东西。

而物理世界里天然存在层级：**行业 → 产业(价值链) → 企业 → 岗位(角色) → 对象(人机料法环：人/机/料/法/环)**。只要给这些物理存在各配一个"孪生体"作为记忆与技能的家，AI 就从"聊天"进入"物理AI"——它的每一个判断都能落到物理对象上，并能写回物理动作。

---

### 2. 框架总览：一脊 · 一体 · 四体系 · 一底座 · 五环节闭环

- **物理存在脊（5 级）**：行业 / 产业 / 企业 / 岗位 / 对象（人机料法环）。越往下越具体、越靠近物理动作。
- **数字孪生载体（一体）**：智能孪生，是持久对象，所有属性附其上。
- **四体系（每个节点都有，静态能力基质）**：记忆体系 / 技能体系 / 知识图谱体系 / **行动体系（手与脚）**。
- **治理底座（一底座）**：横切四层四维，保证可控、可审计、可平权。
- **五环节闭环（动态运转流）**：感知 → 认知 → **决策** → 执行 → **自我进化**。与四体系正交——体系是"对象拥有什么"，闭环是"对象如何运转"。

四者关系：**脊**提供"存在层级"，**体**提供"附着家"，**四体系**提供"对象的能力、认知与行动"，**五环节闭环**提供"能力如何流动成价值"，**底座**提供"约束与可信"。

> 决策体系 = 认知与执行之间的枢纽层（输入信号+记忆+图谱/技能，经情景推演/多目标权衡/约束校验，输出建议与动作）；自我进化 = 闭环的回灌引擎（评估信号驱动资产层复利）。两者补齐后，物理AI闭环（感知·认知·决策·执行·进化）完整闭合。

> 行动体系 = 物理 AI 真正"干活"的接口：脑（技能·记忆·知识图谱）驱动行动决策，分化为**数字世界的手**（写回系统）与**物理世界的脚**（闭环设备/环境），经**人机协同闸门（人在回路）**输出到物理对象，构成"小的世界模型"闭环。这就是"人机协同的智能体工业互联世界"的落点。

---

### 3. 物理存在脊：五级

| 级 | 含义 | 承载对象 |
|---|---|---|
| 行业 | 宏观、知识平权 | 预设库 / 案例 / 第⑥路信号 |
| 产业 | 价值链拓扑 | 代工·设备·设计·存储·封测 等节点 + 国际↔国内对照 |
| 企业 | 租户、私有集成 | UNS 事件流、回写审计、现状 profile |
| 岗位(角色) | 角色级 action | 25 个 Agent persona |
| 对象(人机料法环) | 物理实体 | 设备 / 物料 / 工艺 / 环境 / 人 |

关键：**对象级是物理AI的落点**——人机料法环把"企业"拆到最小可感知、可控制的物理单元，孪生与推理在此处真正与物理世界一一对应。

---

### 4. 四体系附着于孪生（每个节点都有）

脊上每个节点都是一个"对象"，都有四类属性：

- **记忆**：学到什么（行业记忆 / 产业记忆 / 企业级记忆 / 角色记忆 / 对象记忆）。
- **技能**：能做什么（预设库 / 25 Agent / agent skills / 设备·ERP·MES 接口 / 岗位动作）。
- **知识图谱**：知道什么关系（行业图谱 / 价值链拓扑 / 竞品·供应图谱 / 岗位关系 / 对象拓扑）。
- **行动（手与脚）**：把认知变成动作——见 §4.1。

记忆·技能·知识图谱三者共同构成一张**完整图谱**：节点 = 对象，边 = 关系（竞争 / 供应 / 价值链 / 对标 / 职责）。这正对应您说的"形成了一个完整的图谱"。而**行动体系让这张图谱从"知道"变成"做到"**——人机协同世界由此建立。

#### 4.1 行动体系：手、脚、人机协同闸门

| 类别 | 表现 | 现状 |
|---|---|---|
| **手**（数字世界写回） | 回写 ERP/MES · UNS 事件发布 · 文档/报告/公众号推送 · 外部 API 集成（企微/招投标）· 浏览器自动化 · 脚本执行 | 能力已有，但分散在各 agent/脚本，未系统化 |
| **脚**（物理/环境闭环） | 网关/OPC-UA 下发设备指令 · 移动端随身（企微 H5/手机版）· 环境感知接入（第⑥路）· 长程任务编排 | 部分已有；长程编排是缺口 |
| **人机协同闸门**（人在回路） | 确认 / 授权 / 撤销 / 可观测回执 | 🔴 真正缺口：未标准化，写回物理/财务须 human-in-the-loop |

> 关键判断：手脚的能力我们**已有七成**，只是散落未命名；真正缺的是把行动层升为一等公民 + **人机协同闸门标准化**。这正是"没想明白"之处——不是没手脚，而是没把它组织成体系。有了手脚，才真正"干活"，才建成人机协同的工业互联世界与"小的世界模型"。

---

### 5. 治理底座（横切四层三维）

合规闸门 · 回写审计 · 权限第③层 · 匿名铁律 · 凭证隔离 · 租户上下文单一真相源。

它让框架"可治理"，从而区别于单点通用 Agent——这正是"工业治理体系"而非"一个工业 Agent"的由来，也与我们既守的凭证铁律 / 匿名铁律 / 审计三合一是一脉相承，只是现在有了归属位置。

---

### 6. 主线：物理世界 ⇄ 数字孪生 一一对应（五环节闭环）

**感知**（网关/OPC-UA/UNS/第⑥路）→ **认知**（孪生中的记忆·技能·知识图谱推理）→ **决策**（决策体系：情景推演/多目标权衡/约束校验，生成建议与可执行动作）→ **执行**（行动层手/脚经人机协同闸门）→ **回写物理**（ERP/MES/设备动作）→ 物理对象状态变化 → 再次**感知**，同时执行结果进入**自我进化**引擎。

这就是您说的"物理世界和现实世界对应上"的那一下：数字孪生是物理对象在数字侧的镜像，五环节让镜像持续与物理对齐。抓住这条主线，其余内容（更多行业 / 更多案例 / 更细对象）都是沿主线渐进展开，不会失焦。

#### 6.1 决策体系：认知与执行的枢纽

决策不是新模块，而是把已有能力组织成"承上启下的决策层"：

- **输入**：感知信号流（实时多源）+ 记忆（历史：行业/产业/企业/角色）+ 知识图谱·技能（关系与能力）。
- **处理**：情景推演 → 多目标权衡 → 约束校验（治理前置，不可逆动作先过闸门）→ 候选动作生成；每个决策**证据可追溯**（事实锚点铁律）。
- **输出**：决策建议（给人审）/ 可执行动作（交执行层）。
- **分层**（沿脊）：行业级情报决策 / 产业级对标决策 / 企业级运营决策 / 岗位级动作决策。
- **北极星**：决策实时化率 MVP ≥ 40% → 稳态 ≥ 85%（越多的决策由系统实时闭环给出，而非人工离线处理）。

#### 6.2 自我进化引擎：闭环的回灌，进化在资产层

自我进化的燃料是**评估信号**：① 执行结果（反馈/成效）→ ② 评估（决策质量/行动效果/记忆准确度）→ ③ 更新四类资产（记忆/知识图谱/技能/策略阈值）→ ④ 回灌认知（下一轮更准）。

关键判断：**进化发生在 Harness 资产层（宝库/案例/预设/阈值），而非模型参数层**。这对应我们"进化单位=资产，非模型"的定位，也是工业 AGI 与通用 AGI 的根本分野——通用 AGI 赌模型自己变聪明，工业 AGI 让"行业知识资产"在评估信号驱动下复利增长。阶梯 L0 静态种子 → L1 运行时事件积累 → L2 评估信号驱动更新 → L3 跨企业复利。

---

### 7. 开放框架原则

- **不追求完备**：框架是开放骨架，不是封闭全集；允许后续持续注入内容。
- **抓主线**：以"物理对象 → 孪生 → 三体系 → 治理 → 回写"为不动的脊，内容在其上生长。
- **渐进展开**：先行业（半导体）满 10 强，再扩产业 / 企业 / 岗位 / 对象；先记忆+技能（较成熟），再升级知识图谱（主线缺口）。
- **用我们的语言呈现**：工业智能体互联 = 智衍对工业互联网智能体的定义。

### 9. 三层落地路线

1. **思想落地**（本文）：框架论证清楚，收口为总纲"记忆即资产 / 四层三维"章。
2. **技术落地**：代码化四级 taxonomy（如 `TAXONOMY` 常量强制结构）；知识图谱 schema（节点=行业/产业/企业/岗位/对象，边=竞争/供应/价值链/对标/职责）；存储选图库或 UNS 关系表；记忆生命周期 write/consolidate/retrieve/forget 成为一等公民；**行动层统一执行总线（工具注册表 + 人机协同闸门 confirm/authorize/rollback/receipt）**；**决策引擎**（输入汇聚 + 情景推演 + 多目标权衡 + 治理前置约束 + 决策事件落库，复用策略阈值 StrategyTuner 只调阈值不调业务数字）；**自我进化闭环**（评估信号采集 → 资产更新：记忆 consolidate / KG 补边 / 技能沉淀 / 阈值微调，L0–L3 阶梯运转）。
3. **应用落地**：每级一个旗舰用例——行业级=知识平权情报推送；产业级=竞品对标决策分身（10 强已地基）；企业级=私有集成运营闭环；岗位级=角色工作台；对象级=设备孪生预警。

### 10. 待论证 / 待决问题

- **Q1** 知识图谱边的第一优先级：价值链上下游 / 竞争 / 供应？（建议价值链打底）
- **Q2** 对象级孪生粒度：设备级子孪生？与 UNS 通道如何一一对应？
- **Q3** 角色记忆个性化边界：角色原型 vs 按租户学习偏好？
- **Q4** 记忆写入通道：仅自动(信号/事件) 还是也支持"人话教它记住"？
- **Q5** 框架对外表述：是否以"工业智能体互联"作为统一品牌语言？
- **Q6** 行动层统一执行总线：工具注册表 vs 现有散落调用，迁移成本如何？
- **Q7** 人机协同闸门第一优先级：先覆盖"写回 ERP/MES"等不可逆动作，还是全动作统一上闸门？
- **Q8** 决策体系第一落地形态：先做"产业级对标决策分身"（10 强案例已有地基）作为旗舰，还是先做全分层通用决策事件记录框架？
- **Q9** 自我进化信号来源优先级：执行结果自动评估 vs 人工反馈（人话评分/纠正）先接哪头？前者自动但噪声大，后者准但需要人参与。
