## 三、与规划的差距（按严重度排序）

### A. 🔴 规划文档过期 —— 自己先"失真"
- `PRODUCT_DEVELOPMENT_PLAN.md` 表头写"v21.0 → v23.0"，但实际已交付 v24–v29（联邦学习、本体自生长、产业链联邦、投产就绪、七缺口、前端修复）。
- `ROADMAP.md`（开源对外版）还停在 v20.1，Near-term 里列的几项其实早做完了。
- **后果**：外部贡献者 / 伙伴 / 自己复盘都失去"真相地图"。**这是最容易修、也最该先修的一项。**

### B. 🔴 生态网络引力 N = 0（战略头号护城河空转）
- 战略文档 §2.3.2 明写"**最大可控杠杆是把 A=1.0 转化为真实生态 N**，天花板能否兑现全系于此"，并设计六柱飞轮（P1 生态引力 → P3 协同进化 → P4 标准话语 → …）。
- 现状：代码已 Apache-2.0 开源（GitHub 已推），但**没有任何一项飞轮在转**——无 GitHub Discussions 运营、无 Good First Issue 池（ROADMAP.md 自己列了却没做）、无"贡献 agent/本体"入口、无伙伴/集成商接入机制、无开放标准对外动作。
- **这是战略与执行之间最大的断层**：技术再强，没有 N，CCI 天花板（0.657）兑现不了。

### C. 🔴 首客与真实场景 = 空
- 北极星指标"决策实时化率"生产环境 ≈0%——我们仍跑 `ZHIYAN_DEMO_DATA=1` 演示数据。
- 路线图 §5.2 待拍板项"首客场景是否定为设备健康/能耗孪生？"**杜先生尚未正式拍板**。
- 真实 OPC-UA / MQTT 设备接入只在 simulated 验证过，**没在客户现场跑过一例**。
- 这是"技术闭环"到"商业闭环"的最后一步，也是卖点从"讲得通"到"被验证"的关键。

### D. 🟠 社交通道真接入 = 未做
- 隐性捕获端点（`/tacit-capture/{channel}`）已建，但只是**API 注入端点**；企微 / 钉钉 / 邮件的**真实 token 鉴权接入**（路线图阶段 2 风险项"社交通道鉴权"）尚未实现。
- 现状：`notifiers.py` 能**往外**发企微/邮件通知，但**往里**收社交信号还靠人工调 API。隐性捕获仍是"演示态"，没变成"生产态"。

### E. 🟠 配置 UI 连通性验证 = 未做
- 路线图 §4.4 铁律："若做配置 UI，必须带连通性验证（否则假接比没有更危险）"。
- 现状：数据源连接器存在，但**带连通性验证的可视化配置 UI 不完整/缺失**。这直接影响"客户自己接数据源"的可信度。

### F. 🟠 对外物料 / 客户证据缺失
- 白皮书有了，但**一页纸卖点、定价框架、竞品对比卡、客户案例、产品 demo 视频**均未体系化。
- 公众号持续运营，但缺"产品能力可视化"物料支撑转化。

### G. 🟡 客户侧安全合规
- 租户隔离、AuthorizationEngine 已有；但等保 / ISO / 审计合规报告 / 国企准入适配未做——对联盟成员、国企客户是准入门槛。
