# 智衍 EvolvIQ · 应用风险与治理白皮书

> 面向企业**风控、合规、审计、IT 治理委员会**的正式文件——系统梳理平台应用风险，给出可落地的治理框架、授权模型、审计与应急机制。本文所有治理机制均对应平台 v20 真实实现，非原则宣示。

---

## 一、定位与范围

### 1.1 为什么需要治理白皮书

智衍将工业 know-how 封装为 20 个可**自主执行**的智能体。自主 = 能力，也 = 风险。当 Agent 能自动锁料、生成 CAPA、再平衡供给时，企业必须回答：

- 它会在什么情况下做错？错了谁负责？
- 谁能放权、放多少、怎么收回来？
- 所有动作可审计、可追溯吗？
- 数据不出厂、不泄露吗？
- 外部依赖挂了，系统会乱来吗？

本文即回答这些问题。

### 1.2 与既有文档的关系

| 文档 | 互补关系 |
|------|---------|
| 企业应用指南 | 本文是其第八章「风险管控」的**深度展开** |
| 技术白皮书 | 本文引用其架构，但从治理视角重述 |
| SECURITY.md | 偏漏洞披露；本文偏**应用层风险与治理体系** |

### 1.3 适用范围

覆盖：授权执行、数据隐私、模型算法、业务运营、合规法律、组织人员六类风险；覆盖演示环境到生产部署全形态。

## 四、治理架构（三层 + RACI）

```
┌─────────────────────────────────────────────┐
│ 战略层：AI 治理委员会（CIO/合规/业务负责人）  │  定策略、批边界、审事件
├─────────────────────────────────────────────┤
│ 战术层：AI 治理小组（业务+IT+合规各1）        │  月度审视、调阈值、管审批
├─────────────────────────────────────────────┤
│ 执行层：业务主管 / IT / 治理员 / 高管 / 专家   │  用、接、配、决、验
└─────────────────────────────────────────────┘
```

| 活动 | 委员会 | 治理小组 | 业务主管 | IT | 治理员 |
|------|:------:|:--------:|:--------:|:---:|:------:|
| 授权边界策略 | A | R | C | C | R |
| 月度效果审视 | I | A | R | C | R |
| 战略动作审批 | A | R | C | - | - |
| 数据源接入 | I | A | C | R | - |
| 阈值微调 | I | A | C | C | R |

A=批准 R=负责 C=咨询 I=知会

## 五、授权治理体系（核心）

### 5.1 授权边界模型（AuthBoundary，9 字段）

每个 Agent 持有独立边界，由 `AuthorizationEngine.evaluate()` 逐动作校验（代码 `authorization.py:368`）：

```
evaluate(boundary, action):
  1. 若 action.type ∈ require_approval_actions → 强制人工（代码371）
  2. 若 action.type ∉ auto_execute_actions   → 强制人工（代码379）
  3. 若 allowed_categories 非空且品类不在内 → 人工（387）
  4. 若 |价格波动| > price_tolerance_pct     → 人工（390）
  5. 若 数量 > max_lock_qty                  → 人工（395）
  6. 若 置信度 < confidence_threshold        → 人工（398）
  7. 若 当日自主次数 ≥ max_daily_autonomous   → 人工（402）
  8. 全部通过 → 自动执行（414）
```

**七道闸门，任一不达标即转人工**——这是平台的硬安全底线。

### 5.2 放权演进路径（三档）

| 档 | 期 | confidence | 自主动作 | 审批动作 |
|----|----|-----------|---------|---------|
| 观察 | 首月 | 0.90 | 仅报告/任务 | 全部 |
| 协同 | 稳定 | 0.75 | 任务+低风险执行 | 资金/实物类 |
| 自主 | 信任 | 0.65 | 多数 | 仅战略级 |

阈值经「策略调参」控制台**实时生效，不需重启**。

### 5.3 人类在环（HITL）强制点

- **战略级动作**永不进 `auto_execute_actions`：加急订单、合同重谈、预算调整、项目重排（见各 Agent 默认边界）
- **金额敏感**：`price_tolerance_pct` 约束单笔波动
- **实物敏感**：`max_lock_qty` 约束自动锁定量（设 0 = 不自动锁实物）

### 5.4 多租户授权隔离

`MultiTenantAuthorization`（代码 425）按租户持有独立边界集合与日限额；`api_key_hash → tenant_id`（`tenant_store.py:25`）确保跨厂数据不串访。

## 六、数据与安全治理

| 控制项 | 机制 | 实现位置 |
|--------|------|---------|
| 多租户隔离 | `X-Tenant-Key` 头 + 行级过滤 | persistence 127/142 |
| 审计隔离 | 日志按 tenant 过滤 | audit.py:27 |
| 出网最小面 | 仅 LLM 端点出网 | `.env` LLM_API_BASE |
| 私有化 | 支持 vLLM/Ollama 不出网 | llm_client OpenAI 兼容 |
| 韧性降级 | 依赖不可达自动回退 | manager.py / db.py |
| 密钥管理 | `.env` 不入库，gitignore | SECURITY.md |

> **关键结论**：平台可纯内网部署，数据不出厂；唯一出网点是 LLM 调用，可用私有化模型彻底闭环。

|------|---------|

## 八、审计与追溯体系

### 8.1 审计日志

- **端点**：`GET /audit/logs`（audit.py:15）
- **内容**：session_id / event_type / actor / detail / tenant_id / 时间戳
- **存储**：数据库优先，不可用时回退内存（audit.py:23-27）
- **隔离**：所有查询按当前租户过滤（audit.py:19）

`log_audit(session_id, event_type, actor, detail, tenant_id)`（persistence.py:86）在每个关键动作落账。

### 8.2 端到端追溯

`apply_execution_result(tenant_id, agent_name, session_id, result)`（knowledge_graph.py:269）将每次执行结果自动写入跨 Agent 知识图谱，带 `tenant` 标记，形成「质量案例→设备→部件→产线」的可追溯链路。

### 8.3 合规证据导出

审计日志 + 知识图谱边 = 可回溯的合规证据链，支持监管检查与内部审。

## 九、韧性与业务连续性（BCP）

| 依赖 | 不可达时 | 恢复后 | 故障域 |
|------|---------|--------|--------|
| PostgreSQL | 回退 SQLite 文件 | 下次启动切回 | 数据层 |
| Neo4j | 回退内存邻接表 | 重建切回 | 图谱层 |
| OPC-UA Server | simulated 模式 | 自动切 live | 接入层 |
| AMQP Broker | simulated 模式 | 自动切 live | 接入层 |

**设计铁律**：除 LLM Key 外，无任何外部依赖必须在线；任一故障系统**永不宕机、永不乱执行**（降级仅影响数据新鲜度，不触发越权动作）。

## 十、合规映射

| 法规/标准 | 对应治理机制 |
|-----------|------------|
| 网络安全等保 2.0 | 多租户隔离、审计日志、最小出网 |
| 数据安全法 / 个保法 | 私有化部署、不出网、留存可控 |
| GDPR（如涉欧） | 数据隔离、可删除（tenant 级） |
| ISO/IEC 27001 | 访问控制、审计、BCP |
| IATF 16949 / RoHS / REACH | compliance_q + CAPA 自动跟踪 |

## 十一、治理运营机制

### 11.1 月度审视清单

```
□ 各 Agent 批准率 / 驳回率（驳回率高 → 收紧阈值）
□ 自主率趋势（异常飙升 → 复核放权）
□ 审计日志抽样（异常动作归因）
□ 新数据源接入评审
□ 法规库更新确认
```

### 11.2 效果指标看板

| 指标 | 含义 | 治理信号 |
|------|------|---------|
| 自主率 | 自主执行占比 | 放权度 |
| 批准率 | 送审批准占比 | 人类信任度 |
| 驳回率 | 送审驳回占比 | Agent 判断质量 |

### 11.3 事件响应流程

```
发现异常 → 治理员暂停该 Agent 边界(enabled=False) →
治理小组归因 → 委员会定级 → 修复(调阈值/改白名单) →
复盘入 Risk Register → 必要时更新法规库
```

## 十二、治理成熟度路线图

| 级 | 名称 | 特征 |
|----|------|------|
| L1 | 观察级 | 全人工审批，Agent 仅出报告 |
| L2 | 协同级 | 低风险动作自主，资金/实物送审 |
| L3 | 自主级 | 多数动作自主，仅战略级送审 |
| L4 | 自治级 | 跨 Agent 编排 + 自适应阈值（路线图远期） |

建议从 L1 起步，每季度评估升一级，**绝不跳级**。
