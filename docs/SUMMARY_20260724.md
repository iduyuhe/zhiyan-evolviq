## 二、新增 9 个企业级 Agent（经营决策大脑）

### P1 · 计划排程 / 能源碳 / 制造成本（v11→v14）

| Agent | 职能 | 种子数据亮点 |
|-------|------|-------------|
| 🧠 **aps_scheduler** | 生产排程、产能负荷、交期承诺 | 6 工单 / 4 工作中心，准时率 83.3% |
| 🌿 **energy_carbon** | 能耗监控、碳排放核算、ESG | 4 产线 / 182MWh 周能耗 / 18.7% 绿电 |
| 💰 **cost_analysis** | 单位成本拆解、降本机会 | 4 产品 / 均本 205.8 元 / 4 降本机会 21 元/片 |

**关键修复**：energy_carbon 的 `result['lines']` 键被 `_plan_for_generic_agent` 当作 OEE schema 解析 → `KeyError: line_name` → HTTP 500。修复为 schema 感知分支（OEE vs 能耗 vs 跳过），避免该键复用引发的崩溃。

### P2 · 需求订单 / 仓储物流（v14→v16）

| Agent | 职能 | 种子数据亮点 |
|-------|------|-------------|
| 📊 **demand_order** | 需求预测、订单履约、S&OP | 4 产品 / 310 万片需求 / 96.5% 满足率 |
| 🚚 **wms_logistics** | 库存健康、物流时效、自动补货 | 2000 万库存 / 11.2 次周转 / 4 物流路线 |

**路由教训**：`demand_order` 必须放在 `aps_scheduler` 之前（否则 aps 的"交期"截获"交期风险"）；`wms_logistics` 必须放在 `supply_chain` 之前且不能含裸词"库存"（否则抢供应链物料查询）。

### P3 · 质量合规 / 经营驾驶舱（v16→v18）

### P4 · 研发新产导入 / 采购供应商管理（v18→v20）

| Agent | 职能 | 种子数据亮点 |
|-------|------|-------------|
| 🔬 **rd_npi** | NPI 项目全生命周期、里程碑 | 4 项目 / 4 阶段 / 1 高风险自动加速 |

## 五、关键教训沉淀

1. **`lines` 键不可复用**：`result['lines']` 被 OEE 和能耗两类 Agent 复用引起 500。修复：engine 按 schema 区分（oee/energy_kwh/跳过）。
2. **ROUTING_RULES 顺序铁律**：新 Agent 必须按语义紧密度插入正确位置，不能追加末尾。必须先验证 `route_goal()` 断言。
3. **关键词子串陷阱**：`procurement_manage` 的"供应商"含 supply_chain 的"供应"子串 → 被提前截获。方案：复合词 + 前置规则。
4. **GitHub 推送**：从中国网络直连 GitHub 被阻断，通过生产服务器（43.153.172.52）bundle + git push 代理。
5. **PAT 权限**：推送 `.github/workflows/` 需要 PAT 的 `workflow` scope，普通 repo scope 不够。
